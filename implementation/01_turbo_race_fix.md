# Turborepo / Next.js `typecheck`–`build` Race — Analysis and Proposed Fix

**Date:** 2026-08-11
**Status:** **CONFIRMED reproducible. Fix validated, then reverted. NOT merged — awaiting DevOps approval.**
**Governing rules:** `docs/05_repository_strategy.md` §14.1 (task pipeline); `docs/07_technology_decision_record.md` §20 (locked tooling); `docs/12_testing_strategy.md` §9 (flaky-test policy).

---

## 1. Root Cause

Three existing facts combine to produce a genuine race:

1. **`apps/{admin,storefront}/tsconfig.json`** includes `".next/types/**/*.ts"` — the standard Next.js App Router route-type include, generated by `next build`.
2. **Root `turbo.json`** declares:
   ```json
   "typecheck": { "dependsOn": ["^build"], "outputs": [] }
   ```
   `^build` means **upstream workspace dependencies'** `build` — **not** the same package's own `build`.
3. Therefore, within a single package, `typecheck` and `build` are unordered relative to each other and Turborepo runs them **concurrently**.

`next build` **deletes and regenerates** `.next/types/**` at the start of its run. `tsc --noEmit` is simultaneously reading those files via the glob it resolved at startup. The file disappears mid-read → `TS6053: File … not found`.

**Why it looks intermittent:** with no `.next/` present, the glob matches nothing and the race has no surface. With a `.next/` present — from a previous local build, a warm CI runner, or a restored Turborepo cache — it fires. So a cold CI run passes and a warm one fails, which reads as flakiness unrelated to the code under review.

## 2. Reproduction and Evidence

Re-verified in this session (not carried over from the prior review):

| Precondition | Attempts | Outcome |
|---|---|---|
| `.next/` **absent** | 1 | ✅ 23/23 tasks pass |
| `.next/` **present** (stale) | 3 | ❌ **3/3 FAILED** |

Command in all cases is exactly what CI runs (`.github/workflows/pr-checks.yml` line 35):
```
pnpm turbo run lint typecheck test build --force
```

Failure output (this session, both apps affected):
```
storefront:typecheck: error TS6053: File '.../apps/storefront/.next/types/app/layout.ts' not found.
storefront:typecheck: error TS6053: File '.../apps/storefront/.next/types/cache-life.d.ts' not found.
admin:typecheck:      error TS6053: File '.../apps/admin/.next/types/app/layout.ts' not found.
```

The error names a file **inside the build output directory of the very package being typechecked**, which is the signature of the race rather than a genuine type error.

---

## 3. Candidate Fix

A Turborepo **Package Configuration** in each Next.js app — extending the root config for that package only:

```jsonc
// apps/admin/turbo.json   (identical file at apps/storefront/turbo.json)
{
  "$schema": "https://turbo.build/schema.json",
  "extends": ["//"],
  "tasks": {
    "typecheck": { "dependsOn": ["^build", "build"] }
  }
}
```

Two files, six lines each. Root `turbo.json` is **not** modified.

### Validation performed

Applied the candidate, deliberately left a stale `.next/` in place (the exact condition that fails 3/3 without it), and ran the CI command twice: **2/2 passed, 23/23 tasks each time.** The candidate was then **removed**; `git status` is clean.

### Alternatives rejected

| Alternative | Why rejected |
|---|---|
| Remove `.next/types/**` from `tsconfig.include` | Silently drops Next.js route type-safety. Harmless today (no routes) but a real regression once routes exist — trades a CI defect for a type-safety hole |
| Make `typecheck` globally depend on same-package `build` in root `turbo.json` | Slows typecheck for all ten packages, including eight that don't need it, and changes the shared contract to fix a two-package problem |
| Serialise CI into separate turbo invocations | Loses Turborepo's parallelism — the reason `docs/05` §4–5 chose it |
| Accept and re-run on failure | Contradicts `docs/12` §9's flaky-test policy, which treats flakiness as a defect to fix |

## 4. Compatibility Analysis

### `docs/05` §14.1 — Task Pipeline

The locked table specifies:

> | `typecheck` | `^build` **for packages whose types are consumed across a package boundary** | Typecheck result cache | Ensures `@nfi/shared` type changes are validated against every consumer before merge |

**Compatible.** Three points:

1. The requirement is **conditional and package-scoped** by its own wording ("for packages whose types are consumed across a package boundary"), not a global uniform rule.
2. Root `turbo.json` keeps `dependsOn: ["^build"]` unchanged for all ten packages — the stated intent (`@nfi/shared` changes validated against consumers) is preserved exactly.
3. The addition is **narrower and additive**: it adds same-package `build` for the two packages whose typecheck genuinely consumes their own build output — a case `docs/05` §14.1 does not address because it predates any Next.js app existing in the repository.

Also checked: **`docs/05` §14.1's `lint` row** — "Depends on: Nothing… fast-fails PRs without waiting on a full build" — is untouched. Lint still runs immediately, preserving fast PR feedback.

### `docs/07` — Technology Decision Record

**Compatible. No new technology.** Package Configurations are a native Turborepo 2.x feature; Turborepo `^2.3.0` is already locked (`docs/07` §20, `docs/05` §4–5). No dependency is added.

### `docs/06` §9 — Project Structure

**Compatible.** No new top-level folder. A per-package `turbo.json` sits alongside the existing per-package `eslint.config.js` and `tsconfig.json`.

### `docs/12` §9 — Flaky Test Policy

**Actively supported.** That section treats flakiness as a defect to fix rather than tolerate; this fix removes a flakiness source.

## 5. Performance Impact

- `admin`/`storefront` `typecheck` now waits on its own `build`. In a cold run this is largely absorbed — `test` already depends on same-package `build` (`docs/05` §14.1), so that build is on the critical path regardless.
- Warm runs are unaffected (Turborepo cache hit).
- Net measured effect across the runs in this session: **no meaningful wall-clock change**; both fixed runs completed 23/23 comparably to a clean unfixed run.
- Eight non-Next.js packages: **zero change**.

---

## 6. CI Impact

**Before:** `pr-checks.yml` fails intermittently on `admin:typecheck`/`storefront:typecheck` with an error naming a build-output file, whenever a runner has a warm `.next/` or restored cache. Reviewers learn to re-run rather than read failures — eroding the merge gate `docs/11` §4.5 depends on.

**After:** deterministic. A `typecheck` failure means a real type error.

**Urgency:** currently latent because PR volume is near zero and nothing has been pushed. Sprint 1 raises PR volume sharply — fixing before then avoids the failure mode establishing itself as normal.
